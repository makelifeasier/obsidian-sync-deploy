# 验收与排错

- 手机显示空白时，先看是否是“新标签页”，再核对侧栏是否选中“搜索”。切到“文件列表”，核对当前 vault 名称，展开目录并打开一篇已知普通笔记。移动设备锁屏或在后台时，先恢复前台并观察同步状态。手机连电脑后，用已授权的 ADB 或 Apple 应用文档共享检查实际文件。每次操作后观察 UI 结果。缺少 USB 条件时，明确设备上的结果待确认。
- 确认缺文件后，对比电脑允许范围、云端路径及文件校验值、手机磁盘和 Obsidian 可阅读状态。仅看数量会漏掉错文件、零字节和名称不同的问题。若某文件落盘为零但应用仍能读取，先备份两端，确认可信副本内容一致后再修复，防止错误版本回传。显示问题无需重置 GSync 状态。
- 本地快照比较可用 `python scripts/compare_vaults.py SOURCE TARGET --exclude '私人目录/' --exclude '密码.md'`。路径是示例，应使用实际批准范围。使用 `--approved-manifest` 可输入只含已批准相对路径的 JSON 数组，未列出的目标文件仍会被标记为额外文件。默认只输出计数，必要时加 `--list-paths`。对测试快照或经过审核的范围使用该工具。它只比较两个磁盘目录，云端校验应通过实际 Drive 元数据单独确认。
- 用隔离测试库验收新建、编辑、附件哈希、重命名、删除与回收站、离线编辑恢复、同时修改及连续冲突。用合成敏感文件验证排除规则。按测试计划清理合成文件，保留必要的回收站记录。再验证正式库比对和重开应用后的配置持久性。
- 交付应记录每端库名、同步目录、OAuth 状态、文件校验、检索索引和引用测试、未测项、常用操作与恢复入口。不要将历史成功、自动脚本或模拟测试当作本轮真实设备验收。
