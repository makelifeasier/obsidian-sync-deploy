# 同步与设备

1. 确定主库和同步方向，记录只需本地保留的资料。迁移前做独立快照，校验备份文件及哈希，保留已有冲突副本。逐设备检查官方 Sync、Syncthing、iCloud 或其他同步任务。只停用覆盖同一库的旧任务。
2. 先建独立测试库和 Drive 测试目录。使用可信插件发布包，记录版本和哈希。若延续既有修正版，检查源码差异、来源和设备兼容性。GSync 1.0.4 曾发生同一分钟重复冲突覆盖副本。该部署的修正版加入唯一后缀和同名检测。使用新版本时先跑重复冲突用例，确认是否还需补丁。插件升级可能覆盖本地修正。
3. Windows 保留现有主库。安卓和 iOS 用独立本地库接入，避免覆盖已有移动库。安卓可用现有文件夹入口或已授权的 USB 传输。iOS 创建库时选择“本地”，使用 Files 或授权的应用文档共享接口导入。隐藏的插件文件夹需要验证是否实际复制成功。部署包只包含已审查的插件程序和无凭据配置，按设备分别启用插件。复制整个库的配置会带入设备令牌与工作区状态，应按经审核的文件清单导入。
4. 每端填写项目的客户端配置并独立登录，所有设备指向同一云端路径，例如 Obsidian/Notes。检查本地测试数据、远端目录已有对象和重复文件，再执行首次同步。空移动库首次接入应观察下载进度，并保持应用前台运行直至完成。若两侧都有文件，先核对差异，避免旧副本覆盖现有笔记或触发删除传播。
5. 根据用户需求设置启动同步和前台定时同步，例如每两分钟一次。三端确认删除位置可恢复。保留敏感资料、隐藏设备配置、令牌和密钥排除规则，核对实际插件的匹配语义。普通附件可按批准范围单独同步。校验时区分隐藏文件、Obsidian 文件列表计数与真实同步文件数。
